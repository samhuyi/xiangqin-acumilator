# 事件 / 聊天「结算数值」体检报告

> 体检对象：`db/seed/events.js`（354 条事件 / 1066 个选项）、`db/seed/chats.js`（112 条对话 / 340 个选项）
> 规则落地：`tools/rebalance-fx.js`（复算脚本，支持 `--dry` 只出报告）、`tools/gen-seed.js` 的 `enrichFx`
> 复算日期：2026-09-20

## 一、发现的问题

| 问题 | 数据 | 说明 |
|---|---|---|
| 存款只动个位数 | 679 / 1047 处存款影响 ≤ 5 元（65%） | 如「点个赞」存款 -4、「发个朋友圈」存款 +4；游戏经济里起步存款 5 千~80 万、一次最便宜的约会 400 元、求婚 6 万 —— 个位数等于没有 |
| 每个选项都铺满 5 项属性 | 1048 / 1048 个选项**恰好**影响 5 项 | 旧规则「随机补 ±1~4 附带影响 + 强制至少 2 正 2 负」导致，出现「妈打电话 → 颜值 +3」「不借钱 → 事业 +4」这类与情境无关的数值 |
| 看不见的幅度 | 非存款影响中 86% 是 ±1~4 | 0~100 刻度上健康每天自然掉 0.22、情绪每天回 0.4，±4 以内就是「一天的自然波动」，写进结算面板只是噪声 |

根因在 `gen-seed.js` 的旧 `enrichFx`：作者没写的属性会**随机补**一个 1~4 的附带影响，再强制「有增有减」，于是把全属性铺满。

## 二、新规则

1. **看得见才算数**
   - 存款：`|v| < 100 元` → 无影响（删键）。参照系：约会 400 / 1200 / 3600 元，相亲渠道 0~6000 元，求婚 60000 元。
   - 属性：`|v| < 5 点` → 无影响（删键）。参照系：一次加班 = 健康 -6 / 事业 +5 / 情绪 -3。
2. **每个选项最多 3 项影响**（幅度大的优先，同幅度存款优先），不再铺满全属性。
3. **不再注入随机旁支、不再强制有增有减** —— 取舍只在作者真的写了取舍时才体现。
4. **作者手写意图优先**：`n_`/`x_` 事件（`tools/seed-more-events.js`、`gen-seed` 的 `EXTRA_EVENTS`）与 `n_c_` 聊天（`tools/seed-more-chats.js`）按原意图 ×2 重算；参考项目继承来的事件/旧聊天直接清洗现有数值。

## 七、「归零」语义（`fx.zero`）与落地效果

`fx.zero: ['health', 'mood', …]` 表示「把这几项压到谷底」。**不是真的归 0** ——
存款 / 情绪 / 健康 / 事业任意一项归 0 都会立刻判负，一条随机事件秒杀玩家等于没玩法。

| 规则 | 实现 |
| --- | --- |
| 谷底 = `FX_ZERO_FLOOR`（**1 点**） | 结算在 `engine.applyFx`，先算普通加减、再统一压到 `min(当前值, 1)`，`delta` 里如实体现 |
| 只认七项基础属性 | `money / health / career / looks / family / mood / affection`，写别的键无效 |
| 同一条选项里「归零 + 加法」不冲突 | 若加法已经扣穿到 0，会被抬回底线 —— 否则「保底 1 点」的承诺会被同一条选项偷偷绕过去 |
| 不参与 `rebalance-fx` 的删噪规则 | `zero` 是独立字段，不会被「存款 < 100 元删键」之类的规则吃掉；`rebalance-fx` 负责保留并清理它 |

**实测（`x_any_checkup` 的「等项目忙完这阵子」，`zero:['health']`）**：

- 归零后 `health=1`，**当场不判负**（`checkEnd` 返回 null）
- **完全不处理 → 第 5 天触发 `sick`（身体亮红灯）结局**（每日自然衰减 0.22/天）
- **连续休息 6 天 → 回到 23.5，脱离危险**（`REST_HEALTH=+4/天` > 0.22/天）

也就是说这是一条**有明确截止日、可对抗**的极端事件：四天内必须改安排，改了就还有救。

> 对比：`zero:['mood']` 不需要玩家做任何事 —— 情绪每天自然回升 `DAILY_MOOD_RECOVER=0.4`，
> 归零只是一记重击（并且会跌进「对象很容易提分手」的危险区），不会拖成结局。
> 真正会「拖死」的只有 `health` 这一项，设计上要格外省着用。
