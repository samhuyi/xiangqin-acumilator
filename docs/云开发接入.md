## 0. 前置说明

- 本工程数据层**只有云开发一个数据源**（本地缓存只是云端数据的快照，用于秒开，不作为兜底）。
- 云端数据不完整 / 读取失败时，游戏会**显示错误页并列出问题清单**（哪个集合为空、哪个读取失败），不再静默回退，方便直接定位云端数据问题。
- 接入只需做两件事：**① 在云端建集合并灌数据**、**② 在 `game.js` 填环境 ID**。

> ⚠️ **硬性前置：必须是正式 AppID。**
> 测试号/游客号（tourist）**不支持云开发**，开发者工具里不会出现「云开发」按钮。
> 必须先注册正式小游戏账号，替换 `project.config.json` 里的 `appid`，再用管理员身份登录工具。

## 1. 注册正式账号 + 开通云开发

### 1.1 注册小游戏账号（首次必须）

1. 浏览器打开微信公众平台 `https://mp.weixin.qq.com` → 右上角「立即注册」。
2. 账号类型选 **「小游戏」**（注意不是「小程序」，两者类目不同、不可互转）。
3. 用未绑定过公众平台的邮箱注册 → 邮箱激活。
4. 主体类型选 **「个人」**（开发测试够用；上线发布才需版号等额外资质）。
5. 填写身份证 + 手机号，用**本人微信**扫码验证管理员身份。
6. 填写游戏名称/介绍，完成注册。

### 1.2 替换 AppID 并登录

1. 登录后进入「开发管理 → 开发设置」，复制 **AppID**。
2. 回到本工程，把 `project.config.json` 里的 `appid` 改成你的新 AppID。
3. 在微信开发者工具用**管理员微信**扫码登录，重新打开本项目。

### 1.3 开通云开发

1. 顶部工具栏点 **「云开发」** 按钮，按提示开通（个人主体有免费额度）。
2. 记录 **环境 ID**（形如 `xxx-1g2h3k4l`），控制台左上角可复制。

> 若「云开发」按钮仍不出现：确认 ① 已是正式 AppID（非 tourist）② 登录微信是该 AppID 管理员 ③ 工具为最新稳定版。仍不行可改用网页控制台开通：`https://console.cloud.tencent.com/tcb`。

## 3. 创建集合并导入数据

1. 云开发控制台 → **数据库**。
2. 新建集合，名称**必须**与下表一致（15 个，一个都不能少）：
   `events、backgrounds、goals、difficulties、channels、date_types、court_styles、style_events、chats、partners、personalities、endings、constants、materials、texts`
3. 逐个集合点 **「导入」** → 选 `db/export/import/` 下同名 `.json` 文件：
   - **首次导入**：冲突处理选 **Insert**（以 `_id` 为主键）；
   - **更新已导入过的集合**：必须选 **Upsert / 覆盖**，或先删光集合内文档再 Insert。
     ⚠️ 只选 Insert 时，已存在的 `_id` 会被跳过，**云端仍是旧数据**（改文案后「没生效」多半是这个原因）。
   - 建议先拿 `_test_events_2.json`（仅 2 条）试通，再导完整的 `events.json`。
4. 导入完成后，可在集合内看到对应数量的文档。

## 4. 设置集合权限（关键，易漏）

默认新建集合对小程序端「不可读」。**必须把每个集合的权限改为「所有用户可读」**，否则游戏端拉取会失败：

1. 云开发控制台 → 数据库 → 每个集合右侧 **「权限设置」**。
2. 选择 **「所有用户可读，仅创建者可读写」**（或自定义安全规则为 `{"read": true, "write": false}`）。
3. 本游戏客户端**只读**，无需放开写权限。

> 15 个集合都要设。批量可用控制台左侧「权限」入口统一配置，或对每个集合单独设置。

已配置完成 —— 项目根目录 `game.js` 中：

## 7. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 改了文案/数值但真机没变 | 重导时只选了 Insert | 已有 `_id` 会被跳过，必须选 **Upsert/覆盖**，或先删光集合再导入 |
| 显示错误页，列出集合为空 | 集合权限未放开 / 未导入 | 按第 4 步设为「所有用户可读」，并确认已导入 |
| 结局页没有「为什么」原因块 | `texts` 集合里没有 `end.reasons` | 重新导入 `texts.json`（Upsert）；控制台会 warn 提示缺哪个 key |
| 点对方头像 / 属性条进的二级页显示英文 key | `texts` 集合里没有 `profile` / `statlog` 文档 | 重新导入 `texts.json`（Upsert）；缺文案时按内置兜底显示中文 |
| 近期经历页 / 信封卡 / 闲聊页显示英文 key | `texts` 集合里没有 `recent` / `envelope` / `chat` 文档 | 重新导入 `texts.json`（Upsert） |
| 有对象（或已相到人待赴约）却找不到「微信闲聊」 | 入口在**「寻找相亲机会」二级页**里（主界面只留两个方向入口），不是主界面上 | 先点「寻找相亲机会」。另外 `CHAT_MIN_AFFECTION` 设得比当前好感度高时题库也会为空 |
| 点「微信闲聊」只看到「（翻了一遍聊天记录…）」这类说明 | `chats` 里没有当前阶段（如 `lead`）的题目 | 重导 `chats.json`（Upsert）；见面前需要 `phases` 带 `"lead"` 的对话。控制台会打一条指名要重导 `chats` 的告警 |
| 行动页 / 结局页页头没有背景图（只有纯色） | 新加的页头图没进 `manifest.js`，或图片还在后台下载 | 跑 `python tools/compress-assets.py` + `node tools/gen-art-manifest.js`；图未就绪时是有意画纯色兜底，下载完会自动补上 |
| 结局页页头配不到插画 | `endings` 集合没有 `art` 字段（旧数据） | 重导 `endings.json`（Upsert）；`art` 取 `happymarry` / `badmarry` / `alone`，控制台会 warn 点出是哪个结局缺 |
| 恋爱后好感度条一直是满的 / 涨到 100 就不动了 | 渲染层没拿到动态上限（旧版把上限写死在 `stat_defs.max`） | 已修复：按 `engine.affectionCap(S)` 取上限（单身 100 / 恋爱后 500）。同时确认 `constants.json` 里有 `AFFECTION_CAP_DATING` |
| 对象头像 / 出身头像不显示 | `backgrounds.avatar` 或 `materials.jobs[].avatar` 缺失 | 重新导入 `backgrounds.json` / `materials.json`（Upsert），字段填职业 key（如 `programmer`） |
| 接触中就出现「要不要孩子 / 见家长」这类婚嫁内容 | `events` 缺 `stage` 字段，或 `chats` 的 `phases` 里多了 `"talking"` | 重新导入 `events.json` / `chats.json`（Upsert）；确认 `constants.RELATION_ORDER` 已导入 |
| 倒计时在接触中还在走 / 刚相到人就被判「期限到了」 | 引擎为旧版本 | 更新 `js/core/engine.js`；只有「单身且无 `lead`」才递增 `singleStreak`（待初遇也暂停），`checkEnd` 也要求当前仍单身 |
| 灵魂拷问 / 暧昧事件一条都抽不到 | `chats` 缺 `kind` / `personalityId`，或对象人格没有对应剧情 | 重导 `chats.json`（Upsert）；跑 `node tools/smoke.js` 会校验「每种人格都有对象 + 都有 grill/flirt 剧情」 |
| 对方从不主动发微信 | `constants.PARTNER_CHAT_RATE` 为 0 或未导入 | 重导 `constants.json`；默认 0.3，即已有对象时每天 30%（还没见面的待赴约阶段不触发） |
| 一直显示「我们还是多当面接触吧」，聊不了天 | 处于「必须出门约会」状态（微信一共聊过 `CHAT_MUST_DATE_AFTER` 次，玩家发起的和对方主动的都算） | 属预期行为：安排一次约会（约会档位任选）即可解锁并把计数清零 |
| 变化页一直说「还没有可展示的变化」 | 云端 `constants` 没有 `STAT_HISTORY_MAX`，或该局还没结算过 | 确认已重导 `constants.json`；结算过一次后即会出现纪录 |
| 事件结算数值忽高忽低（显示 +8，第二天却对不上） | 旧版引擎对 `fx` 有 ±25% 随机浮动 | 已移除：结算值 = 事件写死的数值 × 固定系数。更新 `js/core/engine.js` 并重导 `constants.json`（旧的 `FX_ROLL_*` 字段已删除）。注意每日自然衰减（健康/颜值/好感度）仍会让第二天数值小幅变化，那是「时间流逝」机制 |
| 相亲图鉴里全是问号 / 一个对象都没有 | `partners` 集合未导入或为空 | 导入 `partners.json`（首次 Insert，更新用 Upsert/覆盖）；确认权限「所有用户可读」 |
| 相亲对象头像显示为占位 / 「（无图）」 | `partners.avatar` 缺失，或对应图片不存在 | 重导 `partners.json`；确认 `assets/images/role/<avatar>-<性别>.png` 存在（文件名必须 ASCII） |
| 图鉴进度清了 / 不跨局累计 | 图鉴进度存在本地（`xq_gallery_v1`），清缓存/换机会重置 | 属预期行为：对象资料始终来自云端，只有「见过谁」的收集进度在本机 |
| `partners=20`（不是 24） | 老版本分页上限写错 | 已修复：客户端按 20 条/页自动翻页 |
| 错误页提示「未检测到云开发」 | 未开通云开发 / 环境 ID 未填 | 开通云开发并在 `game.js` 填环境 ID |
| `events=20`（不是 105） | 老版本分页上限写错 | 已修复：客户端按 20 条/页自动翻页 |
| 部分集合为 0、其余正常 | 该集合权限未设 / 未导入 | 逐个集合复查「所有用户可读」+ 文档数 |
| 报 `env not found` | 环境 ID 填错 | 核对控制台左上角环境 ID |
| 报「格式不正确，请检查是否为 JSON Lines」 | ① 传了 `.jsonl` 扩展名；② **选错了文件**：传了 `db/export/<集合>.json`（JSON **数组**格式，是 gen-seed 的中间产物，不是导入文件） | 导入文件只有一处：**`db/export/import/<集合名>.json`**（每行一个对象、无数组括号）。内容或扩展名不对，控制台报的都是这一句 |
| 仍报「格式不正确」 | 文件末尾多空行 / 带 BOM / CRLF | 重新执行 `node db/import.js`，脚本已处理这三点 |
| 集合里是空的 | 冲突处理选错 / 被覆盖 | 冲突处理选「Insert」重导 |
| `wx.cloud` 为 undefined | 基础库过低 | `project.config.json` 的 `libVersion` 用 `latest`（已默认） |
| 报 `Cannot read properties of undefined (reading 'skip')`（events/chats 等大集合读取失败） | 翻第二页（skip=20）时 SDK 偶发返回异常集合引用，同步异常被误记为集合读取失败 | 已修复：`provider-cloud.js` 单页拉取加防御 + 失败自动重试 2 次（重试时重取 database 句柄），错误信息带 `skip=xx 页` 定位；重新编译即可 |
| 报 `Cannot read properties of undefined (reading 'money')`（选出身背景时崩） | 云端 `backgrounds` 的 `init` 字段缺失 | 现在 `backgrounds.init` 缺失会直接显示错误页并点名该条记录；云端侧请复查 `backgrounds` 集合每条是否含 `init` |

## 8. 数据更新（改内容零代码）

改参考项目数据后，重跑两步再重导：

```bash
node tools/gen-seed.js [参考项目路径]   # 重新抽取种子
node db/import.js                        # 重新生成导入文件
```

然后在云控制台对应集合「导入」覆盖即可，`js/` 下引擎代码无需改动。

## 9. 新增/改文案时的集合对照

逻辑层不含任何文案，改动都是「改数据 → 重导集合」。常见对应关系：

| 想改什么 | 改哪个集合 | 备注 |
|---|---|---|
| 界面/旁白文案、结局原因模板 | `texts` | 结局原因在 `end.reasons`，支持 `{goal}/{progress}/{day}` 等变量 |
| 「对方资料」页文案 | `texts` | `profile` 文档：标题/返回/空态 + 各行标签（`age`/`job`/`trait`/…） |
| 「近期变化」页文案 | `texts` | `statlog` 文档：标题/分节标题（`currentTitle`/`sessionTitle`/`dayTitle`/`totalTitle`）/关键事件（`eventTitle`）/「从 x 变为 y」模板（`fromTo`）/空态 |
| 「近期经历」页文案 | `texts` | `recent` 文档：标题/返回/空态/分节标题（`eventTitle`/`optionTitle`/`resultTitle`） |
| 相亲结果页信封卡文案 | `texts` | `envelope` 文档：标题/徽标/花销标题 + 各行标签（`name`/`job`/`trait`/`family`/`condition`/`age`/`extra`/`place`/`hint`） |
| 微信闲聊页文案 | `texts` | `chat` 文档：标题/返回/发送/**结束闲聊按钮（`finish`）**/我/空态/涨跌/回复/**题库为空时的说明（`emptyLine`/`emptyHint`）** |
| 两个行动二级页的标题与副标题 | `texts` | `play` 文档：`seekPageTitle`/`seekPageSub`（找对象）、`seekPageTitlePartner`/`seekPageSubPartner`（已经有对象时）、`upgradePageTitle`/`upgradePageSub`（其余安排）；操作页按钮文字是 `seekTitle`/`seekSub` 与 `otherTitle`/`otherSub` |
| 结局页页头画面 | `endings` | 每条的 `art` 字段：`happymarry`（修成正果）/ `badmarry`（被逼婚）/ `alone`（一个人），对应 `assets/images/end/end_<art>_<性别>.jpg`；`id → art` 的唯一真源在 `tools/gen-seed.js` 的 `ENDING_ART` |
| 结局页页头小标签 | `texts` | `end.headTag` |
| 微信闲聊场景与效果 | `chats` | `opener` 开场白、`options[].affection/mood` 增量、`phases`/`minAffection`/`weight` 决定出现时机 |
