## 二、发现并修复的问题（2 个）

### Bug 1 —— 读档后分手心情档位失真（数据丢失）
- **位置**：`js/ui/render.js` `saveGame()` / `resumeGame()`
- **现象**：`relSpent`（关系内累计花费）只存在于内存，未写进存档、读档也不还原。
- **影响**：分手心情三档由「相处天数 + 关系内花费」共同定档（引擎 `breakupTier`）。一旦发生存读档，`relSpent` 归零 → 无论相处多久、花了多少钱，分手都只按**最轻档**处理，三档机制形同失效。
- **修复**：`saveGame` 持久化 `relSpent`，`resumeGame` 还原 `relSpent`。
- **回归**：ui-smoke「存读档往返」断言 `relSpent=4321` 存读一致；edge-smoke 静态守卫。

### Bug 2 —— 对局结束后存档未清除（可恢复到「僵尸局」）
- **位置**：`js/ui/render.js` `renderEnd()`
- **现象**：进入结局页时不清存档。从结局页直接关掉小游戏、或点「回到标题」后，仍会显示「继续游戏」。
- **影响**：读档恢复到死亡属性下的 `play` 界面，而结局页不再重现 —— 玩家进入一个无法正常结束的中间态。
- **修复**：`renderEnd()` 进入结局页即 `clearSave()`（广告奖励另存独立 key，不受影响）。
- **回归**：ui-smoke「结局清档」断言 `renderEnd` 后存储中无存档；edge-smoke 静态守卫。

## 三、重点边界验证（未发现问题）

- **分手清零**：分手后 `chatCount` / `mustDate` / `relSpent` 全清零、回到单身；新对象不被上一段的账锁成「必须约会」。
- **分手心情三档**：当天零花费 → ratio 档；相处 20 天 → set 档；相处 40 天 → zero 档；三档确实分离。
- **结局优先级**：达成目标优先于破产/抑郁；破产优先于抑郁；病倒优先于抑郁；到点单身 → forced。
- **好感度动态上限**：接触中 ≤100、恋爱后 ≤500，阶段切换与 `applyStat` 均不击穿。
- **长跑稳定性**：120 局随机策略，属性全程无 NaN / 越界，全部收敛到某个结局。
- **边界输入**：当天分手、`advanceDays(500)` 大跨步、两局状态相互独立 —— 均无异常。
- **云链路分页**（前次修复）：仅文档数 >20 需翻页的集合曾崩，现单页防御 + 重试 + 精确定位。

## 五、遗留观察（非阻塞）

1. **结局页可被系统回收后丢失结局展示**：现在结束即清档是正确取舍；若后续希望「重开还能回看上一局结局」，需把 `over` / `ending` 也持久化并让读档直达结局页（当前未做）。
2. **`saveGame` 未持久化 `currentEvent`**：存档只发生在日界/结算后，随机事件进行中不会存档，读档会重掷当天随机事件 —— 属可接受行为。
3. **测试夹具随机性**：`findDate` 成功率与各项概率取值随机，新增用例需重试或固定 seed，避免假失败。
